# 配置与管理交互

管理页面通过 `src/api.ts` 使用公开 Admin JSON API，诊断操作通过 Command/Event 协议。管理控制面不进入 Agent Graph。端点、鉴权、secret 字段和 revision 规则以[根目录契约](../../frontend-backend-contract.md)为准；安装和进程管理以[发布说明](../../distribution/README.md)为准。

## 实例与任务

总览和系统页展示后端返回的健康组件、版本与能力；请求失败区分网络不可达、鉴权失败、校验失败和 revision 冲突。健康异常不改写诊断生命周期。

任务列表展示问题、状态、当前阶段、profile 和更新时间。打开任务后读取快照和审计；提交澄清、Skip、Resume、Cancel、目标确认或审批时，使用该快照提供的操作与待办标识。

全局 Session 页只展示关联 run、节点/编排类型、创建/更新时间、消息数和派生状态。原生生产 loop 使用一个诊断 Session；兼容 Graph 使用隔离的节点 Session。Session 不是业务状态来源，页面不能编辑消息、跨任务挂载 Session、直接删数据库行或手工回放模型历史。

## 配置编辑

配置页提供模型端点、凭据、超时、streaming，以及诊断策略和节点设置。用户编辑的是本地草稿，后端负责严格校验与原子保存。

1. 加载公开配置及 revision。
2. 编辑草稿，使用 validate 检查错误和警告。
3. 保存携带原 revision；冲突时保留草稿并刷新配置。
4. 展示已生效版本及“只影响新任务”的说明。

已有 run 继续使用不可变配置快照。前端不读取配置 YAML、环境变量、SQLite 或 SDK RunState，也不自行重算后端策略。

API Key 作为 write-only 输入发送；已配置状态或掩码用于展示，不当作新凭据回传。不把凭据存入 localStorage、URL、诊断事件或日志。

## 环境与插件

环境页提供“环境与子服务”“服务插件”和“高级目录”三个视图。日常操作使用表单，完整目录 JSON 用于批量维护和扩展元数据。

日常接入按“选择环境 → 选择子服务 → 添加插件 → 选择类别 → 选择并配置”操作，上方范围选择器始终标明当前环境和子服务。环境卡片展示子服务和接入数量，选定环境后展示其子服务，选定子服务后只展示归属它的接入；新插件自动绑定该环境与服务。

首次使用先创建环境，保存后直接进入子服务创建。环境可选测试、预发布或生产模板；标识自动生成，浏览器时区预填，别名、区域、停用开关收进选填区域。子服务以业务名称为主要输入，简称和版本可选；保存返回的目录立即用于选择，无需等列表轮询。停用环境仍可查看和编辑，但不能新增服务或接入。无法读取目录或目录只读时，页面说明原因并禁用写入操作。

“添加插件”先显示类别，再显示该类别的已安装连接器。数据库包含 SQLite/PostgreSQL，日志包含文件日志/SSH 日志，主机诊断包含 SSH 固定检查；知识库、流量和其他连接器也保留类别，未安装连接器时说明如何由管理员启用。

工作区在桌面与侧栏、右侧窗口各保留 32px 间距，中等宽度为 24px；窄屏导航改为顶部，内容两侧各保留 20px。配置卡片分区使用统一留白，连接方式以可选卡片放在连接主表单。

所有内置插件显式提供内置驱动、MCP、CLI 和 SSH 探针选项；MCP/CLI 隐藏原生数据库、主机和路径必填字段，按所选数据类型展示 MCP 映射或程序输入。接入约定折叠区提供协议和输入输出例子，明确服务由后端执行、MCP 数据位置预绑定、CLI 需要协议适配器。切换数据类型后仅保存适用于当前类型的工具映射。

“其他连接器”可直接选择“自定义 MCP / CLI 连接器”，不依赖已存在的接入。用户选择数据类型，再填写连接地址或程序，以及必填的接入名称、用途和使用步骤；适用场景和调用示例可选。内置插件预填说明，允许按业务调整。说明按实例独立编辑，示例使用标准只读工具名及 JSON 参数，数据源标识自动绑定；页面告知这些内容随诊断快照提供给定位节点。前端字段及后端投影的正式定义见根级契约。

SQLite 主要填写数据库文件位置；PostgreSQL 填主机、数据库和只读账号，端口、Schema 与 SSL 默认值预填。文件日志填写后端服务器目录及相对文件名；SSH 日志填写远端主机、绝对日志目录与相对文件名，多行可配置多个文件，通配符仅用于文件名。SSH 主机检查使用固定检查集合，可通过勾选限制范围。SSH 私钥和指纹文件明确指向后端服务器；密码可按需填写。其他连接器按后端公开 Schema 展示表单，复杂结构保留扩展输入。

同一子服务可反复添加相同插件，每次生成独立实例和数据源标识；新接入不复制其他实例的位置或凭据。已有接入通过“管理配置”单独编辑，已绑定的环境与子服务固定；迁移通过新增接入完成。数据源自动包含所属子服务，其他同环境服务和节点可在高级设置中关联。旧接入按其 source 关联服务展示，未关联服务的旧接入保留“环境级历史接入”管理入口。保存只提交当前接入；停用接入时同时停用其数据源，重新启用时用数据源开关选择恢复范围。保存与检查期间禁用范围切换与其他编辑入口，避免异步结果覆盖正在编辑的新草稿。

默认操作为“保存并检查连接”，也可“仅保存”。两步分别反馈：配置保存成功后，即使检查失败也不提示保存失败或重复创建接入。SQLite 默认检查第一个启用的数据库，高级设置可指定检查库；日志检查目录是否可访问。连接检查不验证全部数据源、不触发诊断或修复，已有诊断继续使用原配置快照。

实例凭据使用后端公开的 `is_set` 状态，轮换通过 `secret_updates` 的 `set`/`clear` 提交，并携带目录 revision。凭据草稿只存在当前接入编辑器内，关闭或成功保存即清空。遇到 409 时保留草稿并刷新目录，用户核对后显式采用最新版本，再次保存；不自动覆盖并发修改。移除接入前展示其数据源数量，再确认移除该实例及其全部数据源。

高级目录编辑器只编辑非敏感 JSON，凭据修改统一进入具体接入的“管理配置”。管理员维护固定连接位置和只读探针，诊断工具不能越过该配置范围访问任意地址或文件。

目标有歧义时，在诊断工作台展示后端生成的候选，再提交确认 Command。目录热更新不改变已有 run 的环境快照；环境边界和只读查询限制见[插件规范](../../backend/docs/environment-plugin-spec.md)。

## 安装与更新展示

根目录安装入口提供 full/backend 模式，`distribution/buglensctl` 负责状态、启动、停止、更新和备份；前后端依赖与制品独立。系统页展示安装命令与版本说明，当前没有网页更新 Control API。

未配置管理 Token 时，当前 MVP 面向本机或可信内网；配置后使用 Bearer Token。Setup Token、用户角色、多租户认证、后端配置草稿服务、网页更新、任务归档和 Session 保留作业尚未实现，页面不得把这些设计设想展示为已可用能力。

静态前端 Token 只适合受控场景，多用户部署的认证由反向代理或独立认证层完成。SSE 代理、CORS 和运行时目录设置见后端[配置与运维](../../backend/docs/configuration-and-operations.md)。
