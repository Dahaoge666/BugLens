# 产品与前端架构

BugLens 前端是证据驱动的诊断工作台。它展示问题、证据、原因假设、独立评测和报告，并让用户完成后端提供的待办操作。HTTP/SSE 和 Admin 公共契约统一见根目录的[前后端对接契约](../../frontend-backend-contract.md)，本文只描述前端职责和交互。

## 当前实现

React 19、TypeScript、Vite 和原生 CSS 构成静态 SPA；请求使用 `fetch`，POST SSE 使用 `ReadableStream`。导航使用轻量 hash 视图，没有额外路由、表单或服务端状态库。

| 视图 | 内容 |
| --- | --- |
| `#dashboard` | 运行概况、健康状态和最近任务 |
| `#tasks` | 任务列表、状态筛选和搜索 |
| `#sessions` | SDK Session 的只读元数据和关联任务 |
| `#settings` | 模型与诊断策略配置 |
| `#environments` | 环境目录、插件信息和连接检查 |
| `#system` | 健康、版本和安装/更新说明 |
| `#run` | 当前打开的诊断工作台 |

新建诊断以弹窗提供问题、profile、环境/服务目标和自主探索选项。工作台包含执行过程、概览、证据与假设三个页签，以及后端提供的澄清、目标确认和审批表单。

总览中的活动图等仍有静态示例内容。断线演示数据和演示操作提示不代表真实诊断或写入结果；后续测试工作见根目录 [TODO](../../TODO.md)。

## 源码职责

```text
frontend/src/
├── App.tsx       # 页面、表单、快照和事件展示
├── api.ts        # HTTP JSON、Command SSE 和历史事件读取
├── types.ts      # 公开协议的 TypeScript 视图
├── styles.css    # 设计变量、全局和页面样式
└── main.tsx      # React 入口
```

按职责需要拆组件，避免提前创建空目录或引入未使用的依赖。前端不导入 Python，不复制 Graph 路由、节点重试、澄清预算或评测门禁。

## 状态与结果展示

运行状态来自后端 Run 快照；连接反馈和表单提交状态只描述浏览器当前操作。SSE 断开或关闭不代表诊断失败或完成。命令结束后读取快照校准展示，恢复时追赶已有事件，事件按 ID/sequence 去重。

可操作按钮以快照的 `available_actions` 为准。revision 或待办 ID 过期时重新读取快照，保留用户草稿，避免自动提交旧答案。客户端不自行决定恢复节点或诊断是否通过。

报告把流程完成与结论可信度分开展示：`confirmed` 展示受证据支持的结论，`inconclusive` 说明限制、未验证假设和下一步验证。假设卡片展示置信度、支持/反对证据和验证步骤；执行过程展示已提交事件及脱敏工具审计，不展示隐藏推理或完整模型消息。

## 交互要求

- 澄清使用后端定义的问题 ID、回答类型和必填规则；目标确认只提交后端候选。
- 网络异常、业务信息不足和执行失败使用各自的文案，不能混为同一个错误。
- 表单保留键盘操作、关联 label 和可见焦点；状态反馈使用 `aria-live`，弹窗需管理焦点。
- 小屏布局保留问题、结果和待办操作，长日志、SQL 和证据 ID 可滚动或换行。
- 不把完整诊断、证据、答案或 secret 保存到 localStorage、URL 或日志。
